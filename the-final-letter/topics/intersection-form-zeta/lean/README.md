# Lean core — intersection form on `E × E`

## Build

```bash
cd the-final-letter/topics/intersection-form-zeta
./lean/check.sh
```

`check.sh` elaborates `Topic.lean`, `EulerMaclaurin.lean`, `GammaProduct.lean`,
`SimpsonPanel.lean`, `Archimedean.lean`, `PolygammaSeries.lean`,
`DigammaEnclosure.lean`, `Enclosure.lean`, `PanelEnclosure.lean` and the
generated `Certificate.lean` against the shared Mathlib at
`~/lean/mathlib4` through [`../../tools/check-lean.sh`](../../tools/check-lean.sh).
The build writes the `.olean` files and prints `[check] OK` for each.

## What is formalised

The rank-three model of the intersection form on the Néron–Severi space of
`E × E`, in the basis `H = {pt} × E`, `V = E × {pt}`, `Δ`:

- `B` — the pairing with Gram matrix `[[0,1,1],[1,0,1],[1,1,0]]`;
- `B_comm` — symmetry;
- `B_self` — `D² = 2(ab + ac + bc)`;
- `A_sq`, `A_dot`, `A_pos` — the ample class `A = H + V + Δ` has `A² = 6`,
  pairs as `A · D = 2(a+b+c)`, and is positive;
- `hodge_inequality` — `6 D² ≤ (A · D)²`;
- `hodge_defect` — the exact defect `2((a-b)² + (b-c)² + (c-a)²)`;
- `hodge_index` — on `A^⊥`, `D² = -(a² + b² + c²)`;
- `hodge_index_nonpos` — on `A^⊥`, `D² ≤ 0`;
- `hodge_index_eq_zero` — on `A^⊥`, `D² = 0` iff `D = 0`;
- `indefinite` — the form is positive on `H + V` and negative on `H - V`;
- `shadow_posSemidef` — any `L * Lᴴ` is positive semidefinite;
- `shadow_quadratic_nonneg` — its quadratic form is non-negative;
- `ldl_posDef` — an exact `L * diagonal d * Lᴴ` with invertible `L` and
  positive `d` is positive definite over `ℝ`;
- `ldl_posDef_rat` — the same implication over `ℚ`;
- `shadowL`, `shadowD`, `shadowP` — the concrete certificate embedded as
  rational data;
- `shadow_factor` — the concrete identity `shadowL * diagonal shadowD *
  shadowLᴴ = shadowP`, by kernel arithmetic;
- `shadowP_posDef` — the concrete `shadowP` is positive definite, with no
  hypothesis left;
- `abs_quad_le_row_sum` — for symmetric `D` with row sums at most `t`,
  `|xᵀDx| ≤ t‖x‖²`;
- `box_ge` — any Hermitian matrix in the box satisfies `A ⪰ G₀ − tI`;
- `posDef_of_box` — with `P` positive definite, any Hermitian matrix in the
  box is positive definite;
- `shadowA`, `shadowE`, `shadowT` — the recorded numerical matrix, the
  half-widths and the operator slack;
- `shadowA_herm`, `shadowA_mem_box`, `shadowE_row` — the C24 checks,
  kernel-checked: symmetry, entrywise containment and the row-sum bound;
- `shadowA_posDef` — the recorded numerical matrix is positive definite.

The file contains no `sorry`, `axiom` or `admit`.

## The enclosure layer

`Enclosure.lean` begins the analytic enclosure layer.  It proves
`digamma_quarter` (T25):

`ψ(1/4) = -γ - π/2 - 3 log 2`,

the value needed for `Ω(0) = -log π + Re ψ(1/4)`.  Mathlib has `ψ(1)` and
`ψ(1/2)` but not `ψ(1/4)`; the proof uses the duplication formula at `s = 1/4`
and the reflection formula.

It also proves the quadratic and cubic log bounds used by the sharp `γ`
squeeze (T26/T27):

`x - x²/2 ≤ log(1+x) ≤ x - x²/2 + x³/3` for `x ≥ 0`,

the strict step inequalities for the two γ sequences (T28/T29):

`aₙ = Hₙ - log n - 1/(2n)` increases, `bₙ = Hₙ - log n - 1/(2(n+1))` decreases,
for `n ≥ 3`;

the squeeze limits (T30/T31), a self-contained rational `log` enclosure
(copied from `partial-sum-plus-tail/Transcend.lean`), and the concrete
rational `γ` interval (T32/T33):

`0.5772135815… < γ < 0.5772260193…`, width `1.24·10⁻⁵`;

the base point of the `Ω` enclosure (T34–T37):

`Ω(0) ∈ [-5.3721937737…, -5.3721813358…]`, width `1.24·10⁻⁵`;

digamma conjugation (T38), `ψ(conj z) = conj ψ(z)` away from the poles, and
`Ω(-t) = Ω(t)` (T39).

## The generated certificate (T91–T100)

`Certificate.lean` is generated by `rust/weil-assembly` from the certified
`4 × 4` interval assembly.  It contains the rational centre `certG0`, the
entrywise half-widths `certE`, the row-sum slack `certT`, and the exact
`LDLᵀ` factors `certL`, `certD` of `certP = certG0 − certT • 1`:

- `certD_pos`, `certL_lower`, `certL_det`, `certL_unit` — the factor is a unit
  lower-triangular matrix with a positive diagonal;
- `cert_factor` — `certL * diagonal certD * certLᴴ = certP`, by kernel
  arithmetic over `ℚ`;
- `certP_posDef` — `certP` is positive definite, with no hypothesis left;
- `certA` — a distinct 12-digit numerical matrix inside the box;
- `certA_herm`, `certA_mem_box`, `certE_row` — symmetry, entrywise containment
  and the row-sum bound;
- `certA_posDef` — the box theorem `posDef_of_box_rat` applied to `certA`.

The generated file contains no `sorry`, `axiom`, `native_decide` or
floating-point literal.  The certificate records a fourth leading minor of
`≈ 2.0·10⁻⁶`, so the positivity is genuine rather than vacuous.

## What is not formalised

- **The Hodge index theorem in general.** The file proves the rank-three
  `E × E` instance. The general theorem for a surface is not in Mathlib and is
  not attempted here.
- **The function-field theorem.** Weil's proof and Deligne's theorem are
  source claims (S1), not Lean theorems.
- **Arakelov intersection theory.** The arithmetic surface, Green's functions,
  the Néron–Tate height and Faltings–Hriljac (S3) are not formalised.
- **The zeta object.** There is no Lean definition of `ζ`, of its zeros, or of
  an intersection form for `ζ`. The dossier records that construction as open.
- **The true matrix is in the box.** `posDef_of_box` proves that any
  Hermitian matrix satisfying the box hypotheses is positive definite.  The
  rational box itself is computed by `rust/weil-assembly` from the Lean
  `Ω` enclosure (T79), the `t`-dependent derivative bound (T90), and a finite
  prime sum; `Certificate.lean` kernel-checks the box data and a numerical
  representative `certA`.  What is still not formalised in Lean is the
  quadrature that turns the pointwise `Ω` enclosure into the density
  intervals, and the prime sum; both are Rust computations with directed
  rounding, cross-checked against mpmath by `tests/test_rust_certificate.py`.

## Why this is the honest core

The finite model is small but it is the part of the function-field proof that
is purely algebraic: the intersection numbers, the ample class, and the
Hodge-index inequality. The analytic input (the correspondence and its trace)
is exactly what the arithmetic side is missing, so formalising more of the
function-field proof would not close the gap this dossier identifies.

The numerical `4×4` assembly and the generated `Certificate.lean` are specified
in [`../HANDOFF-RUST.md`](../HANDOFF-RUST.md) and implemented in
[`../rust/weil-assembly`](../rust/weil-assembly).
