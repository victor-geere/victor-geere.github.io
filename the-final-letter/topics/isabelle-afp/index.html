Why the split H = c • H2 is genuine

The source writes H = 1/sqrt 2 • H2. The Lean proof separates the two ingredients: H2 * H2 = 2 • 1 (T3) and c * c = 1/2 (T4), so (c • H2) * (c • H2) = (1/2) • (2 • 1) = 1 (T5). These are exact rational and quadratic-surd identities, not rfl padding; they are the normalisation argument the source itself performs in H_inv.

Open items and gaps

  1. The AFP is not surveyed. 972 entries and 10,068 theory files remain outside this dossier. The inventory item is a corpus, not a single result.
  2. The source predicates are not in Lean. A faithful translation would define state, unitary, gate, and the dimension-indexed matrix type, then prove the gate lemmas at the source's level of generality. The present Lean core is deliberately the concrete 2 × 2 shadow.
  3. Bell entanglement is not a Lean theorem. Only the determinant-type obstruction is computed. A Lean proof would need a vector-space definition of product state and a proof that no pair of unit vectors tensors to a Bell vector.
  4. No-cloning is not formalised. This is the most substantial theorem in the entry and would require the Cauchy–Schwarz and inner-product development of No_Cloning.thy.
  5. CNOT and phase-gate algebra is computational only. C3 and C4 are exact sympy checks, not Lean theorems.
  6. No connection to the RH programme was found. The entry is a quantum-computing library. Its placement under archive/rh-proof/ is a filing fact, not evidence of an RH proof. This is recorded as a negative finding.
  7. File-count discrepancy. The inventory says 15,416 files; the checked tree has 15,424. The difference is unexplained and immaterial to the mathematics, but it is not hidden.
  8. Cold-cache build cost. The first Mathlib import on a cold filesystem cache can take several minutes; the Lean build itself is 5–7 seconds once the oleans are warm.

Python layer

python/programme.py is an exact sympy model. It contains the gate matrices X, Y, Z, H, CNOT, S, T; the helpers gate, gate_sequence, dagger, matrix_equal, is_unitary, kron; the Bell-state functions bell_state, norm_squared, is_normalised, measurement_probabilities; and the product-state functions product_obstruction, is_product_state, product_state.

The module has no import-time side effects and raises ValueError on invalid shapes or labels. It uses exact surds and exp(I*pi/4), not floating point.

cd the-final-letter/topics/isabelle-afp
python3 -m pytest -q tests
# 7 passed in about 0.2 s

Example:

from python.programme import H, X, Z, matrix_equal, bell_state, product_obstruction
assert matrix_equal(H * X * H, Z)
assert product_obstruction(bell_state("00")) != 0
