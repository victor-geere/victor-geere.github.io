The Von Mangoldt Sieve That Computed log rad(n)

A linear-sieve recurrence for the wrong function — and how it was caught by a validated explicit-formula assembly.

Round rh45 · companion to routes-abc.html §5.3 · evidence: rigorous/route_c_assembly.log, Mathlib ArithmeticFunction/VonMangoldt.lean · machine-checked counterexample: lean/Rh45/VonMangoldtSieve.lean

Abstract

The prime side of the Weil explicit formula needs the von Mangoldt function Λ(n) = log p if n = pk and 0 otherwise. In the numerical assembly of Route C the prime sum was computed from a “linear sieve” that used the recurrence f(p·i) = f(i) when p | i and f(p·i) = f(p) + f(i) when p ∤ i (with p = minFac(p·i) and f(p) = log p). We prove that this recurrence does not compute Λ: it computes exactly log rad(n) = Σp|n log p, the unique additive (not completely additive) function that agrees with Λ on prime powers. The two functions coincide precisely on the prime powers, and differ at the very first composite n = 6: Λ(6) = 0 while log rad(6) = log 6. In the actual run this replaced Chebyshev’s ψ(x) by Σn≤x log rad(n) (about 5.9× larger at x = 2000), shifted the prime sum by 0.15184578545037, and produced a spurious residual of −0.15171179 against a rigorous budget of 6.5×10−5. The fix — an exact sieve marking prime powers — makes the rigorous prime sum agree with mpmath to 4.9×10−12 and the assembly validate at −9.08×10−9 ≤ 6.5×10−5. The finite counterexample 6 is machine-checked in Lean.

Keywords: von Mangoldt function; radical; linear sieve; additive arithmetic functions; Chebyshev ψ; explicit formula; interval arithmetic; Lean 4.

1. Why Λ appears

For an even test function g with Fourier transform φ, the Weil explicit formula used in Route C reads

2Σγ>0 φ(γ) = Φ(1) + Φ(0) + (1/2π)∫ℝ φ(t)Ψ(t) dt − Σn≥2 (Λ(n)/√n)(g(log n) + g(−log n)),

where Ψ(t) = −log π + Re ψ(1/4 + it/2) is the archimedean factor. The prime side is a weighted sum of the von Mangoldt function

Λ(n) = log p  if n = pk (p prime, k ≥ 1),    Λ(n) = 0 otherwise,    Λ(1) = 0.

The kernel chosen for the Route C assembly is the modulated Gaussian g(u) = e−u²/2cos(14u)/√(2π (with rational centre θ = 14), whose Fourier transform is φ(t) = ½(e−(t−14)²/2 + e−(t+14)²/2). Because g decays rapidly, the prime sum truncates at n ≤ 2000 with a rigorous tail 1.2×10−8 (Chebyshev input ψ(x) ≤ (log 4 + 4)x, the Lean prime_tail_input). The whole point of the truncation is that the remaining error is controlled — which makes any error in the Λ(n) values immediately visible as a failure of the identity.

2. Two functions: Λ and log rad

Definitions

For n ≥ 1 let rad(n) = ∏p|n p be the radical (rad(1) = 1), and define

L(n) := log rad(n) = Σp|n log p,    L(1) = 0.

Thus L(2) = log 2, L(4) = log 2, L(6) = log 6, L(12) = log 6, L(30) = log 30.

Both Λ and L are supported on n ≥ 2, both take the value log p at n = p, and both satisfy Λ(pk) = L(pk) = log p. That is where the resemblance ends:

  • Λ is supported on the prime powers; it is zero at every composite with at least two distinct prime factors.
  • L is positive at every n ≥ 2 and, more structurally, is additive on coprime arguments: for gcd(m,n) = 1, rad(mn) = rad(m)rad(n), hence L(mn) = L(m) + L(n).

In fact L is the unique additive (over coprime arguments) function that agrees with Λ on prime powers: an additive function is determined by its values on prime powers, and L(pk) = log p = Λ(pk). Equivalently, writing an additive function as f(n) = Σpk∥n f(pk), the function L is the one that is constant along the powers of each prime, f(pk) = f(p). The von Mangoldt function is not additive: at m = n = 2, Λ(4) = log 2 while Λ(2) + Λ(2) = 2 log 2; and at m = 2, n = 3, Λ(6) = 0 while Λ(2) + Λ(3) = log 6. The second failure is the one the sieve reproduces.

3. The faulty sieve and what it computes

The code below was intended to fill an array lam[n] with Λ(n). It is a “linear sieve” loop that generates every composite n once as n = p·i with p = minFac(n) the smallest prime factor of n and i = n/p (so necessarily p ≤ minFac(i), and p ∤ i exactly when n has more than one prime divisor). 

def sieve_lambda(n):                    # BUGGY
    lam  = [0] * (n + 1)
    primes, comp = [], [False] * (n + 1)
    for i in range(2, n + 1):
        if not comp[i]:
            primes.append(i); lam[i] = log(i)
            for j in range(i * i, n + 1, i):
                comp[j] = True
        if i > 1:
            for p in primes:
                if p * i > n: break
                comp[p * i] = True
                if i % p == 0:
                    lam[p * i] = lam[i]            # branch A:  p | i
                    break
                else:
                    lam[p * i] = lam[p] + lam[i]   # branch B:  p ∤ i
    return lam

Branch A is correct for Λ: if p | i then p·i and i have the same set of prime divisors, so they are either both powers of the same prime or both have at least two distinct prime divisors; hence Λ(p·i) = Λ(i). Branch B is the error: when p ∤ i and i > 1, the number p·i has at least two distinct prime divisors, so Λ(p·i) = 0, not log p + Λ(i).

Theorem (what the buggy sieve computes)

Let f(1) = 0, f(p) = log p for primes p, and for every n = p·i with p = minFac(n) let f(n) = f(i) if p | i and f(n) = f(p) + f(i) if p ∤ i. Then for every n ≥ 1,

f(n) = L(n) = log rad(n) = Σp|n log p.

Proof. Strong induction on n. For n = 1 both sides are 0; for prime n, f(n) = log n = log rad(n). Let n ≥ 2 and write n = p·i with p = minFac(n), i = n/p < n. By the induction hypothesis f(i) = log rad(i).

  • Case p | i. Then p already divides i, so n and i have the same set of prime divisors and rad(n) = rad(i). Hence f(n) = f(i) = log rad(i) = log rad(n).
  • Case p ∤ i. Since p = minFac(n), every prime divisor of i exceeds p, so in particular p ∤ rad(i) and therefore rad(n) = rad(p·i) = p·rad(i). Hence f(n) = log p + log rad(i) = log rad(n). □

The theorem also shows the bug is not an indexing accident: it is a wrong function, forced by the recurrence.

Corollary (when the two agree)

f(n) = Λ(n) if and only if n is 1 or a prime power (n = pk). In particular the first disagreement is at n = 6 = 2·3: f(6) = log 2 + log 3 = log 6 ≠ 0 = Λ(6).

Remark on terminology. It is tempting to call the culprit an “Ω-type” function, since Ω(n) (the number of prime factors counted with multiplicity) and log n are completely additive and obey the same-looking law f(ab) = f(a) + f(b). The output is not Ω, however: it is the additive function L = log rad. The distinction matters because the two laws differ exactly in the branch that broke: for a completely additive g, branch A would read g(p·i) = g(i) + g(p), whereas the sieve’s branch A sets f(p·i) = f(i). Branch A is therefore the law of an additive function that is constant on prime powers — and the additive function constant on prime powers with f(p) = log p is log rad.

4. Iterating the process on two sample functions

The cleanest way to see the forced output is to run the recurrence by hand. Take n = 12: the sieve reaches it as 12 = 2·6 with p = 2 | 6, so branch A gives f(12) = f(6); and 6 = 2·3 with 2 ∤ 3, so f(6) = f(2) + f(3) = log 6. Hence f(12) = log 6 = log rad(12), whereas Λ(12) = 0. The contamination entered once, at 6, and branch A then propagates it to every 2k·3l.

5. Quantitative consequences

A single value error would be harmless if the weights were tiny, but the explicit-formula weights are 1/√n and the kernel is not yet decayed at the relevant n. The effect on the Route C prime sum is measurable exactly.

5.1 The summatory function is not ψ

Taking summatory functions,

Σn≤x L(n) = Σp≤x log p · ⌊x/p⌋,     ψ(x) = Σn≤x Λ(n) = Σpk≤x log p.

The left sum counts each prime once per multiple, not once per prime power, so it is the summatory function of a much larger arithmetic function. At x = 2000:

Σn≤2000 Λ(n) = ψ(2000)1994.45158

5.2 The shift in the prime sum

For the modulated Gaussian with θ = 14 and truncation N = 2000, write PS(f) = Σn=2N (f(n)/√n)(g(log n) + g(−log n)). Then

The difference is reproduced term by term by Σn ((L(n)−Λ(n))/√n)(g(log n)+g(−log n)), whose summand vanishes exactly on the prime powers and is nonzero at 1666 of the indices 2 ≤ n ≤ 2000. In the actual assembly run, with the faulty sieve the explicit formula produced

RHS − LHS = −0.15171179,    budget = 6.499×10−5   ⇒  FAILED,

the residual being the (sign-flipped) prime-sum shift. The discrepancy is enormous compared with the rigorous tails — a classic case of a structural error that is invisible in the small and obvious in the large.

6. The fix, and its verification

Λ is not additive, so an additive recurrence cannot produce it. The correct, and equally cheap, route is to mark prime powers directly: for each prime p, walk p, p², p³, … ≤ N and set Λ = log p; every other index is zero. 

def sieve_lambda(n):                    # FIXED
    lam  = [0] * (n + 1)
    is_p = [True] * (n + 1)
    for p in range(2, n + 1):
        if is_p[p]:
            pk = p
            while pk <= n:
                lam[pk] = log(p)        # Lambda(p^k) = log p
                pk *= p
            for m in range(p * p, n + 1, p):
                is_p[m] = False
    return lam

Equivalently, one may use a genuinely multiplicative route and Möbius inversion, Λ = μ * log, i.e. Λ(n) = Σd|n μ(d) log(n/d), or the divisor identity Σd|n Λ(d) = log n — both are standard and both avoid the additive assumption entirely.

Verification after the fix

  • Point check. The rigorous prime sum at N = 200 is −0.672453122081 against mpmath’s −0.672453122076: agreement to 4.9×10−12, the level of the engine’s rounding slack.
  • Assembly. With both the sieve and a second, unrelated bug in the exponential routine fixed, the validated assembly gives RHS − LHS = −9.07873×10−9 against the budget 6.499×10−5, i.e. |residual| ≤ budget (route_c_assembly.log).

7. The machine-checked counterexample

The smallest counterexample is a finite fact and is checked in Lean 4 against Mathlib’s ArithmeticFunction.vonMangoldt (Rh45/VonMangoldtSieve.lean): 

theorem vonMangoldt_six : Λ 6 = 0 := by
  rw [vonMangoldt_eq_zero_iff]; decide

theorem vonMangoldt_not_additive : ∃ m n : ℕ, Λ (m * n) ≠ Λ m + Λ n := by
  refine ⟨2, 3, ?_⟩
  rw [vonMangoldt_six, vonMangoldt_apply_prime (by decide),
      vonMangoldt_apply_prime (by decide),
      ← Real.log_mul (by norm_num) (by norm_num)]
  norm_num
  exact ne_of_lt log_six_pos

vonMangoldt_six is Λ 6 = 0 via Mathlib’s vonMangoldt_eq_zero_iff : Λ n = 0 ↔ ¬IsPrimePow n; the second theorem exhibits (m,n) = (2,3), which the faulty branch B turns into log 2 + log 3 = log 6 > 0. Both build with the standard axiom footprint [propext, Classical.choice, Quot.sound] and no sorry. The general theorem of §3 is proved on paper; the counterexample is what a proof assistant can pin down without formalising the sieve loop itself.

8. Lessons

  1. A sieve embodies a recurrence, and a recurrence embodies a function class. The loop above is a correct linear sieve — for the additive function log rad. Reusing it for Λ silently changes the object being summed.
  2. Coincidence on primes is not correctness. Λ and log rad agree on all n ≤ 5 and on every prime power; a spot check on 2, 3, 4, 5 would have passed. The first failure is at 6.
  3. Validated assemblies localise errors. Because the Route C residual is compared against an explicit budget of proved tails, a 0.15 discrepancy could not hide: it was 2300× the budget. Without the budget, a “roughly right” identity would have looked acceptable.
  4. Small residual difference is the fastest diagnostic. The exact match PS(log rad) − PS(Λ) = 0.15184578545037 = the run’s residual identified the failing term immediately; the summatory ratio 5.9 then explained why.
